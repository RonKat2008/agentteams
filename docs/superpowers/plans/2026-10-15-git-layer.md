# agentteams Git Layer (Plan 3 of 4) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make agentteams git-aware. Each task gets its own worktree and branch. A pre-commit hook blocks commits that touch files another agent has exclusively claimed. A post-commit hook reports commit summaries to the hub. `create --new-repo` creates the GitHub repo; `join` clones the team repo. Tasks finish with `agentteams done`, `agentteams pr` and `agentteams merged`.

**Architecture:**
- **Hub:** gains a few small services, all transactional and all validated with shared zod schemas: commit dedupe, a batched claim check, claim-override logging, an invite preview, and a mark-merged step.
- **CLI:** gains a `git.ts` helper module, a git-hooks installer and a `git-hook` internal subcommand, plus the commands `worktree`, `done`, `pr` and `merged`. It also gets repo bootstrap for `create --new-repo` and clone-on-join.
- **External tools:** git and gh run only through `CliDeps.exec`, so tests drive real `git` in temp dirs and fake `gh`.

**Tech Stack:** Node 22, TypeScript (NodeNext ESM), Kysely + better-sqlite3, Hono, commander 15, vitest, git ≥ 2.40, gh ≥ 2.40.

**Spec:** `docs/superpowers/specs/2026-10-15-agentteams-design.md`. This plan covers §3: A (`--new-repo`), B (existing-repo verification and default branch) and joining (clone). It covers all of §6. §3 "Collaborator access" is in Plan 4, because it needs hosted identity.

## Global Constraints

- Everything in Plan 2's Global Constraints still holds: ESM, `.js` imports, strict TS, no API keys in repo files or `~/.codex`, hooks never wedge the agent, idempotent installers with `.bak` for files outside the repo, and push after every commit.
- **Git hooks never wedge the user's git.** If the hub is unreachable, there are no credentials, the response is unparseable, or anything is thrown, print a one-line `agentteams: warning: …` to stderr and exit 0. The single exception is that pre-commit exits 1 when the hub positively reports a conflicting exclusive claim held by another agent and `AGENTTEAMS_ALLOW` is not `1`.
- The hub client timeout in git hooks is 2000 ms.
- **Branch name:** `at/<agent>/<task>` (e.g. `at/ronit-claude/4`). **Worktree path:** `<parent of main repo root>/<repo basename>.at/<agent>-<task>`.
- **Managed git hook files** start with `#!/bin/sh` and contain the line `# agentteams-managed`. An existing non-managed hook is moved once to `<hook>.agentteams-prev` and chained, running first; its non-zero exit aborts pre-commit. If `core.hooksPath` is set, do not write anything: warn and print the two lines the user can add themselves.
- The git hooks directory is resolved with `git rev-parse --path-format=absolute --git-path hooks`, and the exclude file with `--git-path info/exclude`. Both work from linked worktrees.
- Commit summaries carry no diff content, only `{sha, branch, message (≤2000 chars), files, insertions, deletions}`. Binary numstat rows (`-\t-\t`) count as 0/0.
- The hub dedupes commits on `(team_id, sha, branch)`, so re-posting is a no-op that returns `{ notified: [], duplicate: true }`.
- `gh` calls are only ever made by commands the user runs explicitly (`create --new-repo`, `join` clone, `pr`), never from hooks.
- **Default branch detection order:**
  1. `git symbolic-ref --short refs/remotes/origin/HEAD`, with the `origin/` prefix stripped.
  2. `gh repo view <slug> --json defaultBranchRef -q .defaultBranchRef.name`, only when a slug is known and `gh` exits 0.
  3. The current branch from `git symbolic-ref --short -q HEAD`.
  4. `main`.
- Text from peers that the CLI prints or injects goes through the format sanitisers added in the Plan 2 fix wave (single-line fields collapse control characters).

## Review Focus

1. **Linked worktrees.** Credentials must resolve, the hooks dir and exclude file must resolve to the common dir, and `.claude/settings.local.json` must exist in the worktree. A Claude Code session opened in `../app.at/ronit-claude-4` must therefore behave like one in the main repo. (Tasks 3, 4 and 5 tests.)
2. **Existing user hooks (husky or a hand-written pre-commit).** They must keep running and their failure must still abort the commit. Re-running install must not chain our hook to itself. (Task 4 tests.)
3. **Hub down or no credentials during `git commit`.** The commit must succeed with one warning line at most, and post-commit must never print a stack trace. (Task 4 tests.)
4. **Initial commit and detached HEAD.** The post-commit summary must work for a root commit (no parent) and report the branch as `HEAD` when detached. (Task 3 tests.)
5. **Join from a directory that already holds a different clone, or a non-empty `./<name>`.** Never clobber it. Refuse with a clear message. (Task 7 tests.)

**Interfaces:**
- **Produces (shared):**

  ```ts
  export const ClaimOverrideInput = z.object({ paths: z.array(RepoGlob).min(1).max(1000), sha: z.string().regex(/^[0-9a-f]{7,40}$/).optional() });
  export const MarkMergedInput = z.object({ task: TaskNumber, pr: z.string().url().max(500).optional() });
  export const InvitePreviewInput = z.object({ inviteCode: <the same schema JoinTeamInput uses for inviteCode> });
  export interface FileConflict { path: string; agent: string; glob: string; expiresAt: string }
  export interface CheckFilesResult { conflicts: FileConflict[] }
  export interface InvitePreview { teamName: string; repo: RepoLink }
  // TaskView gains: mergedAt: string | null
  ```
- **Produces (hub services):**
  - `checkFiles(ctx, actor, input): Promise<CheckFilesResult>`: returns active claims that are **exclusive**, held by **other** agents, and whose glob matches a path. There is one entry per (path, claim), sorted by path then agent.
  - `recordClaimOverride(ctx, actor, input): Promise<{ owners: string[] }>`: computes the same conflicts. If there are none, it returns `{owners: []}` and logs nothing. Otherwise it logs a `claim_overridden` event with payload `{paths (the conflicting ones, max 20), owners, sha?}` and sends each owner an `fyi`: `"<actor> committed over your claim on <path list, max 10> (AGENTTEAMS_ALLOW=1)"`.
  - `markMerged(ctx, actor, input): Promise<TaskView>`:
    - Only the orchestrator may call it (`requireOrchestrator(…, 'mark tasks merged')`).
    - The task must have status `done`, otherwise `conflict`: `task #N is not done yet`.
    - If it is already merged, return `conflict`: `task #N is already merged`.
    - Set `merged_at` and log `merged` `{task, branch, pr?}`.
    - If the assignee isn't the actor, send the assignee an `fyi`: `Task #N (<title>) was merged<: pr>. You can delete its worktree.`
  - `previewInvite(ctx, input): Promise<InvitePreview>` takes no auth. It validates the invite exactly as `joinTeam` does (expiry, revoked → same errors) but creates nothing.
  - `recordCommit` dedupes. Inside the existing transaction it looks up `(team_id, sha, branch)` first, and if a row exists it returns `{ notified: [], duplicate: true }` with no event and no messages. A fresh insert returns `{ notified, duplicate: false }`.
- **Migration `002_git_layer`:**
  1. Delete duplicate commit rows, keeping the lowest `id` per `(team_id, sha, branch)`.
  2. Create the unique index `commits_team_sha_branch_unique` on `(team_id, sha, branch)`.
  3. Add a nullable text column `tasks.merged_at`.
  - Use only portable Kysely schema builders plus one portable `DELETE … WHERE id NOT IN (SELECT MIN(id) … GROUP BY …)` via `sql`.

### Task 4: Git hooks (installer and runners)

**Files:**
- Create: `packages/cli/src/install/gitHooks.ts`, `packages/cli/src/gitHooks.ts`
- Modify: `packages/cli/src/commands/install.ts` (`runInstallers` also installs git hooks; the report gains a `git` line), `packages/cli/src/main.ts` (an internal subcommand `git-hook <pre-commit|post-commit>`) and `packages/cli/src/paths.ts` (reuse the node/bin path helper the agent hooks use)

**Interfaces:**
- **Produces:**
  ```ts
  export type GitHookName = 'pre-commit' | 'post-commit';
  export async function installGitHooks(deps, repoPath: string): Promise<{ status: 'installed' | 'unchanged' | 'skipped'; detail: string }>
  export async function runPreCommit(deps): Promise<number>   // exit code
  export async function runPostCommit(deps): Promise<number>  // always 0
  ```
- **Managed script.** `<node>` and `<bin>` are single-quoted absolute paths, built the same way the agent hook commands are. Each script ends with the stable marker `--agentteams-managed` added in the Plan 2 fix wave:
  ```sh
  #!/bin/sh
  # agentteams-managed
  prev="$(dirname "$0")/pre-commit.agentteams-prev"
  if [ -x "$prev" ]; then "$prev" "$@" || exit $?; fi
  exec '<node>' '<bin>' git-hook pre-commit --agentteams-managed
  ```
  The post-commit script is the same, but the last line is `'<node>' '<bin>' git-hook post-commit --agentteams-managed || true`, and the prev invocation is `"$prev" "$@" || true`.
- **Installer rules:**
  - Find the hooks dir with `gitPath(deps, repoPath, 'hooks')`.
  - If `hooksPathConfigured` returns a value, return `skipped` with a detail containing the two `exec` lines for the user to add.
  - For each hook:
    - If the file is managed (it contains `# agentteams-managed`), rewrite it only if the content differs, and return `unchanged` if every hook is identical.
    - If an unmanaged file exists and there is no `.agentteams-prev` yet, rename it to `<hook>.agentteams-prev`. If a prev already exists as well as an unmanaged file, refuse with `skipped`: `"<hook> and <hook>.agentteams-prev both exist; merge them manually"`.
    - Write the file with mode 0755.
- **`runPreCommit`:**
  1. Resolve the credential for `deps.cwd` with `resolveCredentialForCwd`. If there is none, return 0 silently.
  2. Get `stagedFiles`. If there are none, return 0.
  3. Call `client.checkFiles(paths)` with a 2000 ms timeout. On error, write `agentteams: warning: could not check file claims (<message>); committing anyway` to stderr and return 0.
  4. If there are no conflicts, return 0.
  5. If `AGENTTEAMS_ALLOW === '1'`, call `claimOverride` (errors ignored), print `agentteams: committing over claims held by <owners> (AGENTTEAMS_ALLOW=1); they have been notified`, and return 0.
  6. Otherwise print to stderr:
     ```
     agentteams: commit blocked — these staged files are claimed by other agents:
       <path>  (claimed by <agent> via <glob>, until <HH:MM>)
     Ask them via send_message, wait for release, or override with: AGENTTEAMS_ALLOW=1 git commit ...
     ```
     and return 1. Sanitise the peer-supplied fields with the format sanitiser.
- **`runPostCommit`:** resolve the credential, or return 0 if there is none. Then `headCommit`, then `client.recordCommit`. Ignore every error except a single stderr warning line when the hub is unreachable. Always return 0.
- **`git-hook` subcommand:** `program.command('git-hook').argument('<name>', …choices).option('--agentteams-managed')`. The action sets `exit.code` to the runner's result. Credential resolution needs `deps.cwd` (git runs hooks at the worktree top level).

### Task 5: `agentteams worktree <task>`

**Files:**
- Create: `packages/cli/src/commands/worktree.ts`
- Modify: `packages/cli/src/main.ts`, `packages/cli/src/install/claude.ts` (export `installClaudeForWorktree`)
- Test: `packages/cli/test/worktree.test.ts`

**Interfaces:**
- **Produces:** `worktreeCommand(deps, task: number, opts: { agent?: ToolKind; base?: string }): Promise<void>`
- **Behaviour:**
  1. Run `requireCredential`. Set `root = mainRepoRoot(deps.cwd) ?? gitTopLevel(deps.cwd)`. If neither exists, error with `not inside a git repository`.
  2. Call `client.claimTask(task)`. A hub error is surfaced as-is, e.g. `only the assignee (dylan-claude) can claim task #4`.
  3. Set `branch = at/<agentName>/<task>` and `path = join(dirname(root), basename(root) + '.at', <agentName>-<task>)`.
  4. If `path` exists, check whether it is already a worktree on `branch`. If so, print `worktree already exists: <path>` and continue to step 7. Otherwise error with `<path> exists and is not this task's worktree`.
  5. Pick the base. It is `opts.base` if given. Otherwise get the team repo from `client.status()` and compute the default branch `d` with `defaultBranch`. For GitHub teams, run `git fetch origin <d>` (on failure, warn and fall back to the local `d`) and use `origin/<d>`. Otherwise use `d`.
  6. Create the worktree. If the local `branch` exists, run `git worktree add <path> <branch>`. Otherwise run `git worktree add -b <branch> <path> <base>`. A non-zero exit is an error that includes git's stderr.
  7. Run `installClaudeForWorktree(deps, cred, path)` when `cred.tool === 'claude'`. It writes the managed hooks into `<path>/.claude/settings.local.json` and runs `claude mcp add --scope local …` with cwd `path`, reusing the existing claude installer internals. It does NOT write the instruction block. Codex needs nothing, since its config is user-level.
  8. Print:
     ```
     Task #<n> claimed. Worktree: <path> (branch <branch>)
     Next: cd <path> && <claude|codex>
     ```
